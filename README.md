# tgsave

[![Python](https://img.shields.io/badge/python-3.10%2B-3776AB?logo=python&logoColor=white)](https://www.python.org/)
[![Telethon](https://img.shields.io/badge/telethon-1.34%2B-2CA5E0?logo=telegram&logoColor=white)](https://docs.telethon.dev/)
[![License: MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)

Userbot, который присылает в чат **только исчезнувшие сообщения**: те, что
собеседник удалил у всех, и одноразовые фото/видео. Обычная переписка тихо
учитывается в журнале и в чат не попадает — архив не забивается.

```
входящее сообщение
      │
      ├── текст ────────────────► журнал (SQLite), в чат не идёт
      ├── медиа ──► копия-документ в CACHE (Избранное)
      │
      └── исчезло?
            ├── собеседник удалил ──► 🗑 шапка + копия в TARGET (чат бота)
            └── одноразовое ────────► 🔥 шапка + копия сразу
```

## Почему userbot, а не бот

Обычный бот получает только те чаты, где он сам участник. Личные переписки
ему недоступны — это ограничение Bot API, а не настройка. Видеть сообщения,
которые пишут **тебе**, и замечать их удаление может только клиент под твоим
аккаунтом, то есть MTProto-сессия (Telethon/Pyrogram).

| | Бот | Userbot |
| --- | --- | --- |
| Личные сообщения тебе | ✗ | ✓ |
| Одноразовые медиа | ✗ | ✓ |
| Событие удаления сообщения | ✗ | ✓ |
| Нужен api_id/api_hash | ✗ | ✓ |

Плата за возможность — файл сессии, который даёт полный доступ к аккаунту.
Ему посвящён раздел [Безопасность](#безопасность).

## Возможности

- **Только исчезающее**: удалённые собеседником сообщения и одноразовые медиа.
  Обычная переписка в чат не дублируется.
- **Текст и медиа**: фото, видео, ГС, кружки, документы, стикеры, опросы,
  геолокация — всё, что было в удалённом сообщении.
- **Медиа без пережатия**: в кэш кладётся документом байт-в-байт.
- **Одноразовые** сохраняются мгновенно, до истечения таймера, и сразу
  показываются в чате с пометкой 🔥.
- **Шапка с контекстом**: кто, когда, тег `#from_username` для поиска.
- **Меню с кнопками**: отправители → их исчезнувшие сообщения → просмотр,
  а по кнопке — и само фото/видео.
- **Дедупликация**: повторная доставка после реконнекта не создаёт дублей.
- **Никакого постоянного диска**: файл живёт в `tmp/` только между
  скачиванием и отправкой.

## Быстрый старт

### 0. Что понадобится

- Linux-сервер с `systemd` и Python 3.10+ (проверено на Ubuntu 22.04).
- Аккаунт Telegram, чьи входящие нужно отслеживать.
- `api_id` и `api_hash` — [my.telegram.org](https://my.telegram.org) →
  **API development tools**. Это ключ приложения, а не токен бота.
- Доступ к коду из Telegram при входе (и пароль 2FA, если включён).

### 1. Установка

```bash
git clone https://github.com/<you>/tgsave.git
cd tgsave

sudo API_ID=123456 API_HASH=0123456789abcdef0123456789abcdef \
     PHONE=+79990000000 TARGET=me \
     bash deploy/install.sh
```

Скрипт создаст пользователя `tgsave`, venv с Telethon в `/opt/tgsave`,
состояние в `/var/lib/tgsave`, конфиг `/etc/tgsave.env` (права `600`) и unit
`tgsave.service`. Сервис включён, но не запущен — сначала вход.

### 2. Вход в аккаунт

```bash
set -a; . /etc/tgsave.env; set +a

runuser -u tgsave -- env API_ID=$API_ID API_HASH=$API_HASH \
  SESSION=$SESSION DATA_DIR=$DATA_DIR HOME=/var/lib/tgsave \
  /opt/tgsave/venv/bin/python /opt/tgsave/login.py send --phone "$PHONE"
```

Код придёт в Telegram от сервисного аккаунта «Telegram». Затем:

```bash
runuser -u tgsave -- env API_ID=$API_ID API_HASH=$API_HASH \
  SESSION=$SESSION DATA_DIR=$DATA_DIR HOME=/var/lib/tgsave \
  /opt/tgsave/venv/bin/python /opt/tgsave/login.py code --code 12345
```

Если включена 2FA, команда ответит `NEED_PASSWORD`:

```bash
TG_PASSWORD='…' runuser -u tgsave -- env API_ID=$API_ID API_HASH=$API_HASH \
  SESSION=$SESSION DATA_DIR=$DATA_DIR HOME=/var/lib/tgsave TG_PASSWORD="$TG_PASSWORD" \
  /opt/tgsave/venv/bin/python /opt/tgsave/login.py password
```

Успех: `AUTHORIZED 123456789 @username`.

### 3. Запуск

```bash
sudo systemctl start tgsave
sudo journalctl -u tgsave -f
```

В логе: `userbot @username: кэш me (id …), бот @bot (id …)`.

### 4. Проверка

Попроси кого-нибудь написать тебе и удалить сообщение у всех — в целевом чате
появится:

```
🗑 Удалено · Имя Фамилия · @username · 29.10 00:52
#from_username

текст сообщения
```

Обычные сообщения в чат не попадут — только удалённые и одноразовые.

## Меню с кнопками

Инлайн-клавиатуру умеет отправлять только бот, поэтому интерфейс живёт в боте,
а сбор — в userbot-е. Создай бота у [@BotFather](https://t.me/BotFather),
напиши ему `/start` и допиши в `/etc/tgsave.env`:

```bash
BOT_TOKEN=123456:AA...
OWNER_ID=123456789   # твой id, узнать: @userinfobot
```

```bash
sudo systemctl enable --now tgsave-menu
```

`/menu` в чате бота:

```
🗑 Исчезнувшие сообщения
Всего: 12 · отправителей: 3

Удалённые и одноразовые. Выбери отправителя:

[👤 виктор · @regretles114 · 9]
[👤 акумов · 3]
[🔄 Обновить]
```

Кнопка отправителя → список (по 8 на страницу, с датой, типом и превью),
кнопки `1…8` → карточка сообщения, `◀️ ▶️` — страницы, `↩️` — назад.

Если у сообщения есть медиа, бот присылает его отдельным сообщением: фото и
видео — картинкой/плеером, остальное — документом. Файл берётся из кэша:
userbot скачивает копию в `tmp/`, бот отправляет и удаляет файл.

## Настройки

| Переменная | Пример | Назначение |
| --- | --- | --- |
| `API_ID` | `123456` | id приложения с my.telegram.org |
| `API_HASH` | `0123…cdef` | hash приложения |
| `PHONE` | `+79990000000` | номер аккаунта, нужен только для входа |
| `TARGET` | `@my_bot` | куда присылать исчезнувшие сообщения |
| `CACHE` | `me` | тихий кэш медиа до удаления (по умолчанию «Избранное») |
| `SESSION` | `/var/lib/tgsave/session` | путь к файлу сессии (без `.session`) |
| `DATA_DIR` | `/var/lib/tgsave` | журнал, временные файлы, состояние входа |
| `BOT_TOKEN` | `123456:AA…` | токен бота для меню (необязательно) |
| `OWNER_ID` | `123456789` | твой id — меню отвечает только ему |
| `TZ` | `Europe/Moscow` | часовой пояс в шапках |

```bash
sudo sed -i 's|^TARGET=.*|TARGET=@storage_bot|' /etc/tgsave.env
sudo systemctl restart tgsave
```

## Что и как сохраняется

| Событие | Действие |
| --- | --- |
| Входящий текст | только журнал, в чат не идёт |
| Входящее медиа | копия-документ в `CACHE` |
| Собеседник удалил у всех | 🗑 шапка + текст или пересланная копия в `TARGET` |
| Одноразовое фото/видео | 🔥 шапка + копия сразу, до истечения таймера |
| Правка сообщения | обновляется в журнале (в чат не идёт) |
| Сообщения в `TARGET`/`CACHE` | игнорируются (защита от петли) |

После отправки копии из кэша сам кэш-дубликат удаляется — в `TARGET` остаётся
рабочая копия, а «Избранное» не пухнет бесконечно.

Журнал `/var/lib/tgsave/saved.db`:

```sql
-- что уже показано как исчезнувшее
SELECT sender, kind, reason, ts FROM saved WHERE surfaced=1 ORDER BY ts DESC;

-- статистика
SELECT reason, COUNT(*) FROM saved WHERE surfaced=1 GROUP BY reason;
```

## Ограничения

- Ловится только удаление **у всех**. Если собеседник удалил сообщение лишь у
  себя, Telegram не присылает событие — узнать об этом невозможно.
- История **до** установки не отслеживается: удалить то, чего userbot не видел,
  он не сможет.
- Медиа удалённого сообщения восстанавливается из кэша, поэтому кэш занимает
  место в облаке Telegram (не на сервере).
- Одноразовое медиа скачивается в момент прихода; если Telegram не отдал файл
  (истёк TTL), в чат уйдёт хотя бы подпись.
- Лимит MTProto — 2 ГБ на файл; меню-бот шлёт фото до 10 МБ, остальное до 50 МБ
  (при превышении — документом, если позволяет).
- Секретные чаты недоступны через API в принципе.
- Использование userbot не описано в правилах Telegram отдельным сценарием:
  ответственность за аккаунт лежит на владельце.

## Безопасность

**Файл сессии равнозначен паролю от аккаунта.** Кто получил
`session.session` — получил доступ к перепискам и возможность писать от твоего
имени; 2FA уже созданную сессию не защищает.

Что сделано в проекте:

- конфиг `/etc/tgsave.env` — `600 root:root`;
- каталог состояния `/var/lib/tgsave` — `700`, владелец `tgsave`;
- файл сессии принудительно `600` при входе и старте;
- `UMask=0077` в unit-файлах;
- systemd-хардненинг: `ProtectSystem=strict`, `ProtectHome=yes`,
  `PrivateTmp=yes`, `NoNewPrivileges=yes`, `ReadWritePaths=/var/lib/tgsave`;
- сервисы работают от непривилегированного пользователя `tgsave`;
- меню-бот отвечает только `OWNER_ID`, остальным — «Нет доступа»;
- в репозитории нет ключей, номеров и id — только код и пример конфига.

Что делать тебе:

- не коммитить `/etc/tgsave.env`, `*.session`, `saved.db`;
- не копировать сессию на другие машины;
- при подозрении на утечку — завершить сессии в Telegram: **Настройки →
  Устройства**;
- сменить пароль 2FA, если он где-то засветился (сессия это переживёт).

## Обслуживание

```bash
# статус и логи
systemctl status tgsave tgsave-menu
journalctl -u tgsave -f
journalctl -u tgsave-menu -f

# перезапуск после правки конфига
systemctl restart tgsave

# статистика
sqlite3 /var/lib/tgsave/saved.db \
  "SELECT reason, COUNT(*) FROM saved WHERE surfaced=1 GROUP BY reason;"

# размер состояния (медиа там не хранится)
du -sh /var/lib/tgsave
```

Полное удаление:

```bash
systemctl disable --now tgsave tgsave-menu
rm -f /etc/systemd/system/tgsave.service /etc/systemd/system/tgsave-menu.service \
      /etc/tgsave.env
systemctl daemon-reload
userdel tgsave
rm -rf /opt/tgsave /var/lib/tgsave
```

Перед удалением заверши сессию в Telegram, иначе она останется активной.

## FAQ

**`NEED_PASSWORD`** — включена 2FA. Заверши вход командой `login.py password`.

**`Cannot find any entity corresponding to "123456789"`** — сессия не знает чат
по числовому id. Укажи `TARGET=@username` или напиши в этот чат один раз.

**Код не пришёл / истёк** — повтори `login.py send --phone …`.

**`AUTH_KEY_UNREGISTERED` / `SessionRevokedError`** — сессию завершили в
Telegram. Удали `session.session` и войди заново.

**Удалённое сообщение не появилось** — собеседник удалил его только у себя,
либо сообщение пришло до запуска сервиса, либо это группа (слушаются только ЛС).

**Как найти всё от одного человека** — тег `#from_username` в шапке, тап
открывает поиск по чату; либо меню `/menu`.

**В чате остался старый архив «📥 …»** — это копии, сделанные прошлой версией.
Их можно удалить: они больше не нужны, меню показывает только исчезнувшее.
