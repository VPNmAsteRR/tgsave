# tgsave

[![Python](https://img.shields.io/badge/python-3.10%2B-3776AB?logo=python&logoColor=white)](https://www.python.org/)
[![Telethon](https://img.shields.io/badge/telethon-1.34%2B-2CA5E0?logo=telegram&logoColor=white)](https://docs.telethon.dev/)
[![License: MIT](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)

Userbot, который копирует **все входящие личные сообщения** в выбранный чат:
«Избранное», отдельный канал или чат с ботом. Текст, фото, видео, голосовые,
кружки, документы, стикеры и одноразовые медиа — всё сохраняется автоматически.

```
Telegram ──► твой аккаунт (Telethon)
                 │
                 ├── текст ─────────────────────────────► чат-хранилище
                 ├── медиа ──► temp-файл ──► документ ──► + файл удаляется
                 └── правка / удаление ──► журнал и пометка
```

## Почему userbot, а не бот

Обычный бот получает только те чаты, где он сам участник. Личные переписки
других людей ему недоступны — это ограничение Bot API, а не настройка. Читать
сообщения, которые пишут **тебе**, может только клиент под твоим аккаунтом,
то есть MTProto-сессия (Telethon/Pyrogram).

| | Бот | Userbot |
| --- | --- | --- |
| Личные сообщения тебе | ✗ | ✓ |
| Одноразовые медиа | ✗ | ✓ |
| События удаления и правки | ✗ | ✓ |
| Нужен api_id/api_hash | ✗ | ✓ |
| Работает без сервера | ✓ | ✗ |

Плата за возможность — файл сессии, который даёт полный доступ к аккаунту.
Поэтому ему уделено отдельное внимание в разделе [Безопасность](#безопасность).

## Возможности

- **Автоматически**, без команд и подтверждений: пришло сообщение — появилась копия.
- **Любой тип контента**: текст, фото, видео, ГС, кружки, аудио, стикеры, GIF,
  документы, опросы, геолокация.
- **Медиа без пережатия**: скачивается и отправляется документом байт-в-байт,
  исходное качество сохраняется.
- **Одноразовые фото и видео** сохраняются сразу, до истечения таймера.
- **Правки** приходят отдельным сообщением с пометкой `✏️ изменено`.
- **Удаления** фиксируются в журнале — копия к этому моменту уже сохранена.
- **Ноль постоянного хранилища на сервере**: медиа живёт в `tmp/` только между
  скачиванием и отправкой.
- **Меню с кнопками**: бот в своём чате рисует инлайн-клавиатуру —
  отправители → их сообщения → текст целиком.
- **Медиа по кнопке**: выбрал фото или видео — бот присылает его в чат
  отдельным сообщением (файл берёт userbot, бот отправляет).
- **Меню только для владельца.**
- **Теги по отправителям**: каждая копия помечается тегом
  `#from_username`, тап по нему открывает все сообщения этого человека.
  При первом сообщении от нового отправителя в чат приходит «визитка» `📇`
  с его тегом — получается живое оглавление.
- **Дедупликация**: повторная доставка после реконнекта не создаёт дублей.
- **Защита от петли**: сообщения в самом целевом чате не копируются, поэтому
  бот с автоответом в качестве `TARGET` не зациклит пересылку.

## Быстрый старт

### 0. Что понадобится

- Linux-сервер с `systemd` и Python 3.10+ (проверено на Ubuntu 22.04).
- Аккаунт Telegram, чьи входящие нужно сохранять.
- `api_id` и `api_hash` — создаются за пару минут на
  [my.telegram.org](https://my.telegram.org) → **API development tools**.
  Это ключ приложения, а не токен бота.
- Доступ к коду из Telegram при входе (и пароль 2FA, если включён).

### 1. Установка

```bash
git clone https://github.com/<you>/tgsave.git
cd tgsave

sudo API_ID=123456 API_HASH=0123456789abcdef0123456789abcdef \
     PHONE=+79990000000 TARGET=me \
     bash deploy/install.sh
```

Скрипт создаст системного пользователя `tgsave`, venv с Telethon в
`/opt/tgsave`, состояние в `/var/lib/tgsave`, конфиг `/etc/tgsave.env` (права
`600`) и unit `tgsave.service`. Сервис будет включён, но не запущен — сначала
вход.

### 2. Вход в аккаунт

```bash
set -a; . /etc/tgsave.env; set +a

runuser -u tgsave -- env API_ID=$API_ID API_HASH=$API_HASH \
  SESSION=$SESSION DATA_DIR=$DATA_DIR HOME=/var/lib/tgsave \
  /opt/tgsave/venv/bin/python /opt/tgsave/login.py send --phone "$PHONE"
```

В Telegram придёт код от сервисного аккаунта «Telegram». Дальше:

```bash
runuser -u tgsave -- env API_ID=$API_ID API_HASH=$API_HASH \
  SESSION=$SESSION DATA_DIR=$DATA_DIR HOME=/var/lib/tgsave \
  /opt/tgsave/venv/bin/python /opt/tgsave/login.py code --code 12345
```

Если включена двухэтапная аутентификация, команда ответит `NEED_PASSWORD`.
Тогда пароль передаётся так (через переменную окружения, чтобы он не попал в
историю шелла и список процессов):

```bash
TG_PASSWORD='…' runuser -u tgsave -- env API_ID=$API_ID API_HASH=$API_HASH \
  SESSION=$SESSION DATA_DIR=$DATA_DIR HOME=/var/lib/tgsave TG_PASSWORD="$TG_PASSWORD" \
  /opt/tgsave/venv/bin/python /opt/tgsave/login.py password
```

Успех выглядит так: `AUTHORIZED 123456789 @username`.

### 3. Запуск

```bash
sudo systemctl start tgsave
sudo journalctl -u tgsave -f
```

В логе: `userbot @username -> me (id 123456789)`.

### 4. Меню (необязательно)

Создай бота у [@BotFather](https://t.me/BotFather), напиши ему `/start` со
своего аккаунта и допиши в `/etc/tgsave.env`:

```bash
BOT_TOKEN=123456:AA...
OWNER_ID=123456789   # твой id, узнать: @userinfobot
```

```bash
sudo systemctl enable --now tgsave-menu
```

В чате бота команда `/menu` открывает архив:

```
📂 Архив сообщений
Копий: 342 · отправителей: 12

[👤 виктор · @regretles114 · 18]
[👤 акумов · 4]
[🔄 Обновить]
```

Кнопка отправителя → список его сообщений (по 8 на страницу, с датой, типом и
превью), кнопки `1…8` → карточка сообщения, `◀️ ▶️` — страницы, `↩️` — назад.

Если у выбранного сообщения есть медиа, бот сразу присылает его в чат: фото и
видео — картинкой/плеером, остальное — документом. Как это работает: бот
создаёт запрос в журнале, userbot достаёт копию из чата, скачивает файл в
`tmp/`, бот отправляет его и удаляет файл. Место на сервере не занимается,
файл живёт секунды.

Ограничения Bot API: фото — до 10 МБ, видео и прочее — до 50 МБ; если не
получилось отправить как фото/видео, бот пришлёт документом.

Инлайн-клавиатуру умеет отправлять только бот — аккаунт (userbot) так не
может, поэтому интерфейс живёт в боте, а сбор — в userbot-е. Доступ проверяется
по `OWNER_ID`: чужим бот отвечает «Нет доступа».

### 5. Проверка

Попроси кого-нибудь написать тебе в личку (или напиши с другого аккаунта). В
целевом чате появится копия с шапкой:

```
📥 Имя Фамилия · @username · 29.10 00:11
#from_username

текст сообщения
```

Тап по `#from_username` открывает поиск по чату — все копии от этого человека.
Для отправителей без username используется `#from_id123456789`.

## Настройки

Все параметры читаются из окружения (обычно `/etc/tgsave.env`).

| Переменная | Пример | Назначение |
| --- | --- | --- |
| `API_ID` | `123456` | id приложения с my.telegram.org |
| `API_HASH` | `0123…cdef` | hash приложения |
| `PHONE` | `+79990000000` | номер аккаунта, нужен только для входа |
| `TARGET` | `me` | куда копировать: `me`, `@username` или id чата |
| `BOT_TOKEN` | `123456:AA…` | токен бота для меню (необязательно) |
| `OWNER_ID` | `123456789` | твой Telegram id — меню отвечает только ему |
| `SESSION` | `/var/lib/tgsave/session` | путь к файлу сессии (без `.session`) |
| `DATA_DIR` | `/var/lib/tgsave` | журнал, временные файлы, состояние входа |
| `TZ` | `Europe/Moscow` | часовой пояс в шапках сообщений |

`TARGET` можно менять на лету:

```bash
sudo sed -i 's|^TARGET=.*|TARGET=@my_storage_channel|' /etc/tgsave.env
sudo systemctl restart tgsave
```

Числовой id работает только если сущность уже известна сессии. Если Telethon
отвечает `Cannot find any entity corresponding to "…"`, используй `@username`
или id с префиксом `-100…` для каналов.

## Что и как сохраняется

| Событие | Действие |
| --- | --- |
| Новый отправитель | «визитка» `📇` с именем и тегом |
| Входящий текст | копия с шапкой и тегом, длинный текст режется на части |
| Входящее медиа | скачивание → отправка документом → удаление файла |
| Одноразовое фото/видео | сохраняется сразу, пока TTL не истёк |
| Медиа с подписью | подпись в caption (до 900 символов) |
| Правка сообщения | отдельное сообщение `✏️ изменено` с новым текстом |
| Удаление сообщения | запись в лог; копия уже в целевом чате |
| Сервисные сообщения | пропускаются |
| Сообщения в целевом чате | пропускаются (защита от петли) |

Состояние хранится в `/var/lib/tgsave/saved.db` (SQLite):

```sql
-- что сохранено
SELECT chat_id, message_id, sender, kind, status FROM saved ORDER BY ts DESC LIMIT 20;

-- сколько всего и сколько успешно
SELECT COUNT(*) AS total, SUM(status = 'sent') AS sent FROM saved;
```

## Ограничения

- Сохраняются только **входящие личные** сообщения: группы, каналы и исходящие
  не затрагиваются.
- История **до** первого запуска не восстанавливается — копируются только
  новые сообщения.
- Лимит MTProto — 2 ГБ на файл; более крупные попадут в журнал как ошибка.
- Секретные чаты недоступны через API в принципе.
- Копии занимают место в облаке Telegram, а не на сервере.
- При массовой пересылке Telegram может ответить `FloodWait`; клиент ждёт
  автоматически, для личной переписки это практически не встречается.
- Использование userbot не описано в правилах Telegram как отдельный сценарий:
  ответственность за аккаунт и его ограничения лежит на владельце.

## Безопасность

Главное: **файл сессии равнозначен паролю от аккаунта**. Кто получил
`session.session` — получил доступ к перепискам и возможность писать от твоего
имени (пароль 2FA при этом не защищает уже созданную сессию).

Что сделано в проекте:

- конфиг `/etc/tgsave.env` — `600 root:root`;
- каталог состояния `/var/lib/tgsave` — `700`, владелец `tgsave`;
- файл сессии принудительно переводится в `600` при входе и при старте сервиса;
- `UMask=0077` в unit-файле;
- systemd-хардненинг: `ProtectSystem=strict`, `ProtectHome=yes`,
  `PrivateTmp=yes`, `NoNewPrivileges=yes`, `ReadWritePaths=/var/lib/tgsave`;
- сервис работает от непривилегированного пользователя `tgsave`;
- меню-бот отвечает только `OWNER_ID`, остальным — «Нет доступа»;
- в репозитории нет ни ключей, ни номеров, ни id — только код и пример конфига.

Что нужно делать тебе:

- не коммитить `/etc/tgsave.env`, `*.session`, `saved.db`;
- не копировать сессию на другие машины и в бэкапы, к которым есть доступ у
  кого-то ещё;
- при подозрении на утечку — завершить сессию в Telegram: **Настройки →
  Устройства → завершить все** (или конкретную), затем войти заново;
- после публикации кода в репозиторий сменить пароль 2FA, если он где-то
  засветился.

## Обслуживание

```bash
# статус и логи
systemctl status tgsave tgsave-menu
journalctl -u tgsave -f
journalctl -u tgsave-menu -f

# перезапуск после правки конфига
systemctl restart tgsave

# статистика
sqlite3 /var/lib/tgsave/saved.db \
  "SELECT COUNT(*) total, SUM(status='sent') sent FROM saved;"

# размер состояния (медиа там не хранится)
du -sh /var/lib/tgsave
```

Полная удаление:

```bash
systemctl disable --now tgsave
rm -f /etc/systemd/system/tgsave.service /etc/tgsave.env
systemctl daemon-reload
userdel tgsave
rm -rf /opt/tgsave /var/lib/tgsave
```

Перед удалением не забудь завершить сессию в Telegram, иначе она останется
активной на стороне аккаунта.

## FAQ

**`NEED_PASSWORD`** — включена 2FA. Заверши вход командой `login.py password`
(см. [Быстрый старт](#2-вход-в-аккаунт)).

**`Cannot find any entity corresponding to "123456789"`** — сессия не знает
этот чат по числовому id. Укажи `TARGET=@username` или отправь в этот чат
сообщение со своего аккаунта один раз, затем перезапусти сервис.

**Код не пришёл / истёк** — повтори `login.py send --phone …`; старый
`login.json` перезапишется.

**`AUTH_KEY_UNREGISTERED` / `SessionRevokedError`** — сессию завершили в
Telegram. Удали `session.session` и войди заново.

**Копии не появляются** — проверь `journalctl -u tgsave`; убедись, что сообщение
пришло в личку после запуска сервиса, а не в группу.

**Сообщения из самого целевого чата не копируются** — так и задумано: они уже
лежат там, а дублирование дало бы петлю, если `TARGET` указывает на бота с
автоответом. Если хранилище — чат с ботом, его собственные сообщения тоже не
дублируются.

**Как найти все сообщения одного человека** — нажми на `#from_username` в любой
его копии либо введи тег в поиск по чату. Соответствие тегов и людей лежит в
таблице `senders`:

```sql
SELECT tag, name, username FROM senders ORDER BY first_seen DESC;
```

**Нужно сохранять и группы** — по умолчанию фильтр `is_private`. Правка одной
строки в `userbot.py` (`func=lambda e: e.is_private`) расширяет охват, но
групповой трафик может быть объёмным.

├── userbot.py              # основной процесс: слушает и копирует
